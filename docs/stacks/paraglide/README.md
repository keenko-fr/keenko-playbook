# Paraglide

- Use one canonical flat catalog per locale.
- Use flat, stable, random human-readable message IDs generated by Sherlock where available.
- Do not rename an established ID because wording or component location changes.
- Reuse an ID only when usages intentionally represent the same product message and should evolve together.
- Import generated message functions directly; do not introduce a Keenko translation wrapper.
- Paraglide owns intentional UI/product copy, including validation/accessibility copy. Editorial/database content remains application data.
- Stable domain/programmatic values remain canonical English and are localized at display/validation boundaries.
- Put plural/select grammar in messages rather than fragment assembly in JSX.
- Use active-locale-aware number/date/currency formatting rather than scattered hardcoded locale identifiers.
- Generated Paraglide modules are compiler-owned, ignored by default, and compiled deterministically before typecheck/test/build.
- Base locale, supported locales, and locale routing are project/product decisions.

See `.playbook/docs/conventions/i18n.md`.
