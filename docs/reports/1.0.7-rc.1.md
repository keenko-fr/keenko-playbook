## Residual plan decision

Nx resolves factories from the currently installed package collection. The old optional-data entry cannot run against rc.0 because that package removed the collection. Nx also does not record durable postcondition-based completion. Generating a new plan can overwrite outstanding work; version-based exclusion cannot prove it ran.

The safe solution is explicit preflight, verification and archival, documented in [canonical migration guidance](../../src/generators/sync/files/docs/core/migrations.md#residual-plan-recovery). An unsatisfied or unknown entry remains pending and runs through its original published owner before archival. An already-satisfied entry requires recorded postcondition review. An executed/completed plan is archived after final checks. The current target then gets a genuinely new Nx plan, which must contain its dependency migration. No empty plan, silent catch, historical factory resurrection or alternate runner is shipped.

The product reproduces the exact rc.0 collection error from the authentic 1.0.6 optional-data plan. Its controlled unapplied fixture must refuse archival, restore published 1.0.6, run its original factory and verify compiler/lint state. The applied fixture runs the original factory before carrying the plan to rc.0. Both verify state and preserve the reviewed plan before proceeding. The clean rc.0 case remains separate.
