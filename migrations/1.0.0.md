# v1.0.0 migration

This release makes the pre-v1 backend and Confect conventions deterministic. Existing consumers that followed earlier ambiguous guidance should reconcile their authored code as follows:

- remove an unnecessary `packages/backend/src/` layer and place owned backend directories directly under `packages/backend/`;
- rename singular `feature/` ownership to `features/` and keep feature files flat by default;
- place Confect specs/implementations under `packages/backend/confect/`;
- move application schemas genuinely used across multiple backend layers to `packages/backend/schemas/`, while leaving feature-local and provider-owned schemas with their narrower owner;
- do not create `packages/shared` until a real second workspace/runtime consumes the same code; when it is earned, expose deliberate package exports/subpaths;
- migrate authored Effect 4 namespace subpath imports to root named imports where the root exports the required API;
- replace canonical Failure payload fields such as `reason` or `code` with `issue`, backed by one canonical finite Issue schema;
- inline simple one-use Confect endpoint schemas and prefer Effect Schema built-ins such as `S.Trim`; keep extracted schemas only when reusable, complex, or semantically meaningful;
- adopt the canonical backend/Confect structural section order from `docs/conventions/backend-file-topology.md` and remove empty sections;
- rerun the consuming repository's canonical Confect codegen whenever specs, schemas, refs, or generated inputs change as part of the migration.

After updating a consuming repository, run its normal typecheck/tests plus `playbook check` against the newly pinned Playbook snapshot.
