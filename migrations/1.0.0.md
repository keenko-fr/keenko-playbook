# v1.0.0 migration

This release makes the pre-v1 backend, Confect, formatting, linting, and UI conventions deterministic. Existing consumers that followed earlier ambiguous guidance should reconcile their authored code and tooling as follows.

The post-KEE-8 Playground dogfood reconciliation intentionally changes several KEE-8 migration assumptions: provider API schemas move out of infra, real external provider capabilities become services from their first real consumer, expected typed Failures use Schema-tagged error values, and infra files no longer use `SCHEMAS` or per-operation sections.

- remove an unnecessary `packages/backend/src/` layer and place owned backend directories directly under `packages/backend/`;
- rename singular `feature/` ownership to `features/` and keep feature files flat by default;
- place Confect specs/implementations under `packages/backend/confect/`;
- move application schemas genuinely used across multiple backend layers to `packages/backend/schemas/`;
- move provider `*ApiDto` schemas from infra into `packages/backend/schemas/<provider>/<resource>.ts`; create the provider directory from the first real provider schema and do not add a speculative `schemas/providers/`, `common.ts`, or `shared.ts`;
- do not create `packages/shared` until a real second workspace/runtime consumes the same code; when it is earned, expose deliberate package exports/subpaths;
- rename frontend `CONSTS` structural sections to `CONSTANTS`;
- move every schema-derived TypeScript type directly below its authored schema declaration and reserve trailing `TYPES` sections for standalone non-schema-derived types;
- reorder persisted resource schema files to `CONSTANTS`, `FIELDS`, `ENTITY`, `INSERT`, `PATCH`, `INTERNALS`, omitting empty sections and keeping `FooDoc` in `FIELDS`;
- replace duplicate equivalent `S.Struct` declarations with aliases or installed structural composition/derivation APIs; preserve the semantic `Fields`, `Foo`, and `Insert` names even when their current schemas alias;
- derive creation contracts from `Fields` when semantics match and keep creation APIs typed as `FooInsert`;
- keep focused persistence-only Patch contracts at the data owner, derive them from shared `Fields`, and keep required fields required unless omission genuinely carries semantics;
- derive persistence Docs with the installed Confect system-field facility instead of manually declaring `_id` or `_creationTime`;
- replace simple trusted one-way `Doc -> Foo` projections with deterministic value-level structural projection such as installed `Struct.omit`, rather than re-decoding solely to drop metadata;
- migrate authored Effect 4 namespace subpath imports to root named imports where the root exports the required API; keep required unstable subpaths such as the supported first-party HTTP APIs when they are not suitably root-exported;
- replace canonical Failure payload fields such as `reason` or `code` with `issue`, backed by one canonical finite Issue schema;
- migrate handwritten expected Failure unions to `S.TaggedError`; do not add redundant type aliases for TaggedError classes;
- preserve useful originating technical errors as internal diagnostic `cause` values where appropriate, but strip raw provider/HTTP/schema causes when mapping to public/server-client Failure contracts;
- migrate real external/substitutable provider capabilities to Effect services from their first real consumer and remove parallel direct-function APIs for the same capability;
- use `make` as the service implementation source and infer the service shape when practical; keep primary/genuine variant Layers on the service class;
- leave lower-level service requirements such as `HttpClient` open on provider Layers and provide concrete implementations at outer runtime/application composition;
- replace raw platform HTTP plus custom callback injection seams with installed Effect-native HTTP/service dependencies when Effect owns the provider workflow; use fake provider services at feature level and fake/test lower-level services at infra level;
- do not add provider retry merely because Effect supports it; introduce retry only with an explicit reliability/latency policy;
- migrate infra file sections to `CONSTANTS`, `ERRORS`, `SERVICE`, `INTERNALS`, `TYPES`, omitting empty sections; remove normal infra `SCHEMAS` and per-service-operation sections;
- keep `E.fn("...")` as the stable operation/tracing identity and make its generator callback anonymous;
- replace pure typed error translations implemented as `catch -> E.fail(...)` with `E.mapError`;
- add named exhaustive provider Issue -> feature Issue mappers at ownership boundaries rather than branching on Failure tags, diagnostic cause, or casting coincident string unions together;
- namespace-import architectural data/features modules (`data`, `features`, or a different-concept prefix such as `usersData` / `usersFeatures`); use named imports by default for infra, schemas, Confect helpers, and ordinary modules;
- inline simple one-use Confect endpoint schemas and prefer Effect Schema built-ins such as `S.Trim`; keep extracted schemas only when reusable, complex, or semantically meaningful;
- adopt the canonical backend/Confect structural section order from `docs/conventions/backend-file-topology.md`, remove empty sections, make separators 140 characters, keep one blank line only before major separators, and add no surrounding blank lines to subseparators;
- rerun the consuming repository's canonical Confect codegen whenever specs, schemas, refs, or generated inputs change as part of the migration;
- migrate the persisted playbook module name from `ui` to `react-ui`; `playbook update --apply` resolves the current preset and replaces the generated snapshot, so no compatibility alias is retained;
- for UI-enabled projects, accept the newly created project-owned `docs/project/ui.md` when it is absent and record durable visual/interaction intent there; updates preserve an existing file, and exact theme values, CSS values, and component implementations remain code/config owned;
- migrate TypeScript repositories to TypeScript 7+ and exact-pin the canonical Ultracite/Oxfmt/Oxlint/`oxlint-tsgolint` version set from `docs/core/tooling.md`;
- add root `oxfmt.config.ts` and `oxlint.config.ts` that inherit Ultracite, use `printWidth: 140`, enable type-aware Oxlint, preserve external/workspace-before-local import grouping, and exclude generator-/manager-/vendor-owned output; strip Ultracite's `endOfLine`, `tabWidth`, and `useTabs` fields so `.editorconfig` remains authoritative for LF and indentation;
- rebuild repository Oxlint overrides from the pinned Ultracite baseline instead of carrying historical exceptions forward; the universal Keenko delta permits hoisted authored function declarations, permits function/type references before their declarations, permits `++`/`--`, enforces top-level `import type` for type-only imports and inline `type` for mixed imports, and treats a leading `_` as an intentionally unused function parameter only;
- check every named caught error and use `catch {}` when the error value is irrelevant; do not use `_` to exempt local variables, array-destructured bindings, or caught errors, and keep unused-variable autofix limited to safe import removal;
- set each deployable artifact's ECMAScript target from the oldest runtime it deliberately supports rather than adopting one universal Keenko year or floating `ESNext`; the Playbook repository itself moves to `ES2023` because its pinned modern Bun runtime supports that target;
- keep generic Ultracite rules such as `sort-keys`, non-null/assertion checks, TypeScript type-definition style, and generic async/Promise policy at their pinned defaults unless a narrowly scoped stack/framework/runtime conflict earns an override;
- expose the canonical `format`, `format:check`, `lint`, `lint:fix`, `typecheck`, and non-remediating `check` scripts, plus `test`, `build`, `codegen`, or `codegen:check` only where applicable;
- make CI consume those check-only scripts rather than auto-fixing or pushing rewritten source;
- when the Effect module is enabled, exact-pin the supported `@effect/tsgo` and `oxlint-plugin-effect` versions, patch TypeScript/Oxlint through `effect-tsgo patch --oxlint`, extend the Effect tsgo Oxlint recommended preset, register `jsPlugins: ["oxlint-plugin-effect/plugin"]`, merge the plugin's `recommended` rules only in Effect-owned source, keep `effect/noTernary` off because Effect has no semantic reason to replace ordinary Keenko conditional-expression syntax, disable generic async/Promise rules in that same Effect-owned scope when `effect/noAsyncFunction` is the more specific owner, disable duplicate plugin-owned `effecttsgo/*` diagnostics without removing semantic/type-aware Effect-tsgo checks, treat the exact overlap list as versioned compatibility data, and keep the TypeScript language-service plugin at `diagnostics: false` to avoid separate editor/LSP duplication;
- for TanStack Start/Router route-definition objects, keep TanStack's inference-sensitive property order above generic alphabetical `sort-keys`; prefer the published TanStack route-order rule through Oxlint when the pinned pairing is executable, never add ESLint solely for that rule, and otherwise disable `sort-keys` only for the route-definition files that need the framework order while keeping it active elsewhere.

These convention changes do not by themselves imply a persisted-data migration or backfill.

After updating a consuming repository, run its normal generation checks plus `bun run check` and `playbook check` against the newly pinned Playbook snapshot.
