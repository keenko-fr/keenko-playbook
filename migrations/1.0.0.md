# v1.0.0 migration

This release makes the pre-v1 backend, Confect, formatting, and linting conventions deterministic. Existing consumers that followed earlier ambiguous guidance should reconcile their authored code and tooling as follows:

- remove an unnecessary `packages/backend/src/` layer and place owned backend directories directly under `packages/backend/`;
- rename singular `feature/` ownership to `features/` and keep feature files flat by default;
- keep backend shared schemas only under `schemas/`, feature-local schemas under their owning feature, and provider DTO schemas under their owning `infra` adapter;
- use `PascalCase` Confect spec function keys and camelCase exported refs;
- keep `confect/_generated/**` and `convex/_generated/**` generator-owned and never edit them manually;
- migrate authored Effect 4 namespace subpath imports to root named imports where the root exports the required API;
- replace canonical Failure payload fields such as `reason` or `code` with `issue`, backed by one canonical finite Issue schema;
- inline simple one-use Confect endpoint schemas and prefer Effect Schema built-ins such as `S.Trim`; keep extracted schemas only when reusable, complex, or semantically meaningful;
- adopt the canonical backend/Confect structural section order from `docs/conventions/backend-file-topology.md`, remove empty sections, make separators 140 characters, keep one blank line only before major separators, and add no surrounding blank lines to subseparators;
- rerun the consuming repository's canonical Confect codegen whenever specs, schemas, refs, or generated inputs change as part of the migration;
- migrate TypeScript repositories to TypeScript 7+ and exact-pin the canonical Ultracite/Oxfmt/Oxlint/`oxlint-tsgolint` version set from `docs/core/tooling.md`;
- add root `oxfmt.config.ts` and `oxlint.config.ts` that inherit Ultracite, use `printWidth: 140`, enable type-aware Oxlint, preserve external/workspace-before-local import grouping, and exclude generator-/manager-/vendor-owned output; strip Ultracite's `endOfLine`, `tabWidth`, and `useTabs` fields so `.editorconfig` remains authoritative for LF and indentation;
- expose the canonical `format`, `format:check`, `lint`, `lint:fix`, `typecheck`, and non-remediating `check` scripts, plus `test`, `build`, `codegen`, or `codegen:check` only where applicable;
- make CI consume those check-only scripts rather than auto-fixing or pushing rewritten source;
- when the Effect module is enabled, exact-pin the supported `@effect/tsgo` and `oxlint-plugin-effect` versions, patch TypeScript/Oxlint through `effect-tsgo patch --oxlint`, extend the Effect tsgo Oxlint recommended preset, register `jsPlugins: ["oxlint-plugin-effect/plugin"]`, merge the plugin's `recommended` rules, keep `effect/noTernary` as the explicit Keenko exception, and disable the plugin-documented overlapping tsgo diagnostics rather than disabling the unconditional plugin rules.

After updating a consuming repository, run its normal generation checks plus `bun run check` and `playbook check` against the newly pinned Playbook snapshot.
